# Linux ownership contract-to-test plan

Base: `961414b2464d1561b42f00bfca01f67b066dd025`. Synthetic disposable Linux CI
only; no Darwin sandbox or signals. Three-hour maximum starting 12:34 UTC,
2026-09-06. Existing accepted R1/R2 and controller contracts stay intact.

| Contract | Fixture / observation | Required result |
| --- | --- | --- |
| TERM-ignoring descendants | Worker, child, grandchild; host PID/start-time and namespace inventory | All owned processes terminated by cleanup deadline; unrelated control untouched |
| New session/group | Descendant spawned detached (setsid), host session/group differs | Cannot leave owned PID namespace; no active member after settlement |
| Closed pipes / leader exit | Detached descendant closes inherited descriptors; leader exits on test command | No success settlement with live owned descendants |
| Pre-session cancel | Adapter run with no provider session event | Exact owned cleanup and one terminal result |
| Timeout/output/cancel race | Bounded flood, late output, repeated cancel | First terminal cause preserved; single settlement; no cross-attempt late output |
| Actual owner loss | Kill only identity-verified disposable wrapper owner | Owned namespace drains; no claim of surviving job completion |
| Outer-client loss | Existing client/daemon ownership separation, where supported | Owner/job remain alive; distinguish missing durable controller owner from cleanup |
| Cleanup uncertainty | Inject failure only into owned cleanup observation | CLEANUP_FAILED/UNKNOWN; controller and channel retry remain durably blocked |
| Namespace settlement race | Hold the actual wrapper's init-state observation ACTIVE for 200ms after cancellation | No settlement until termination becomes observable; independent host inventory still verifies actual cleanup |
| Missing backend identity | Actual bwrap sends metadata to wrong FD; FD4 worker barrier stays closed | CLEANUP_FAILED/UNKNOWN; no worker entrypoint execution |

Every new process fixture has an absolute expiry and a separate watchdog. The
watchdog checks host start time and test identity before exact-PID signaling.
Host namespace scans establish membership, not namespace-local PID numbers or
bwrap leader disappearance alone. Watchdog intervention fails the proof and is
reported; it is never counted as successful boundary cleanup.

Provider decision: update the existing table with one proposed read-only
subscription boundary, preserving unsupported/live-unperformed distinctions.
No supervisor deployment, credential provisioning, egress or inference.

## Demonstrated Counterexample And Repair

Raw-head CI `42aa982` (run 34034857124) observed owned namespace init host PID
3542/start 13718 still R at the wrapper's cancellation settlement. The external
test client saw it gone slightly later. This is a real premature-settlement
counterexample, not a persistent escape; the first static review missed it.

The Linux backend now supplies bounded trusted FD3 metadata and holds FD4 until
the wrapper observes and pins the exact namespace init PID/start-time/inode.
The effective profile digest includes `linux-pid-namespace-v1`. Both start and
resume use the same preparation. Terminal receipts include this identity/state.
Normal exit and cancellation wait for init termination as well as pipe closure
and group disappearance. Unknown observation remains CLEANUP_FAILED, with the
existing durable retry block. Output/provider JSON cannot substitute for FD3.

Cleanup budget remains killGraceMs + cleanupMs (3500ms by default; 2100ms in the
new proof). Backend startup observation consumes the existing run timeout.
Missing metadata never releases worker execution. Immediate cancellation before
backend identity can be established is conservatively uncertain, not a claimed
successful cleanup. Real profiles remain refused. Parent-death proof covers an
established worker boundary, not every pre-exec spawn race or durable-owner crash
recovery.

The observed Linux rule is supported by
[PID namespace lifetime semantics](https://man7.org/linux/man-pages/man7/pid_namespaces.7.html)
and the [kernel namespace teardown](https://raw.githubusercontent.com/torvalds/linux/v5.15/kernel/pid_namespace.c):
namespace init teardown prevents new members and waits for remaining tasks.
This is distinct from bwrap monitor exit. No new process supervisor was added.
