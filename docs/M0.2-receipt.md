## Effective profile and compatibility

Trusted channel `workerPolicy` defines the absolute pinned executable SHA-256,
tools, business read/write roots, private 0700 stateRoot, timeout and limits.
The compiler freezes version, channel/provider/model identity, canonical roots,
runtime exceptions, auth source name, environment key names and digest. Secrets
are excluded from the digest. Script fixtures additionally pin their entrypoint.
No ambient executable override or PATH search selects a provider.

Job envelopes may provide `readRoots`, `writeRoots`, and `outputLimits`; these
are included in the canonical payload and can only narrow channel grants.
`requestedTools: []` means no tools. Existing stored task fields remain readable.
Unconfigured real worker channels now fail ISOLATION_UNSUPPORTED before spawn.
No production definitions, running daemon or JARVIS routing were changed.

Resume requires the same effective digest in authoritative session state.
Unknown legacy sessions and changed policy cannot restore broader permission;
the channel records a reset, then starts fresh under current policy.

Environment is constructed from HOME, PATH, TMPDIR, LANG, LC_ALL,
CLAUDE_CONFIG_DIR and CODEX_HOME only. HOME/config/temp live beneath a dedicated
profile directory outside business roots. No user home/settings are inherited.
The disabled-by-default Claude subscription-token mechanism would read only a named
`FACTORYV2_*` token source and supplies CLAUDE_CODE_OAUTH_TOKEN. Missing tokens
fail AUTH_REQUIRED; API billing keys are never inherited or substituted. All
non-fixture profiles are currently rejected as ISOLATION_UNSUPPORTED before
credential access/spawn until the enforcement blockers are resolved.
No real credential was read or copied in these proofs. Installed CLI help only:
Claude 2.1.259; Codex 0.153.0-alpha.5. No generating CLI call was made.

Claude availability uses `--tools`, distinct from `--allowedTools` preapproval;
safe/restricted modes and empty setting/MCP sources suppress customizations.
The protocol fixture verifies exact flags; this does not certify real CLI tool
behavior. Codex profiles requiring exact tool availability are explicitly
unsupported. The old read-only sandbox flag is not treated as filesystem proof.

## Bounds and cleanup

Defaults/maxima: line 1 MiB, stdout 8 MiB, events 4096, invalid lines 32,
stderr 64 KiB. Channel/job values must be positive safe integers and can only
decrease limits. Default timeout 300 seconds, absolute ceiling 1800 seconds;
TERM grace 500 ms and cleanup deadline 3000 ms after grace. Overflows are
non-success, never successful clipped responses. Raw chunks are checked before
concatenation. Readers/timers are cleared, process handles unreferenced at
settlement, and later events are ignored.

Processes start in owned groups and cancellation does not depend on a provider
session ID. Linux uses bubblewrap filesystem/network/PID namespaces and
die-with-parent. macOS uses sandbox-exec with explicit business/runtime read
exceptions, writes only to private worker state/granted roots, and directory-only
traversal exceptions. Network is denied in deterministic profiles. Runtime
exceptions include sealed OS libraries/dyld, the pinned executable/fixture, and
necessary directory enumeration; these are not business-data grants.

## Explicit blockers and limitations

- Real provider profiles are explicitly blocked before spawn. The current isolated namespace has
  no provider egress. Native keychain subscription auth and Codex exact-tool
  availability are unsupported; no fallback to ambient settings/API billing.
  This prevents claiming full M0.2 provider readiness or advancing to M0.3.
- macOS group ownership does not confine a deliberately daemonizing descendant
  that leaves its process group. Such lifecycle enforcement is unsupported;
  the tested group cleanup must not be generalized to escaped sessions.
- Early malformed macOS sandbox experiments denied a root directory read during
  Node exec. Six exact probe PIDs remained in kernel `UEs` state despite TERM/KILL:
  7764, 8127, 8593, 8877, 9753, 10130. Their promises recorded CLEANUP_FAILED.
  Corrected directory-only exceptions prevent recurrence in subsequent tests,
  but those early kernel-stuck processes are an unresolved local cleanup blocker.
  Their diagnostic supervisors were terminated by exact PID. No broad process
  match, reboot, production cleanup or system-setting change was performed.
- Path confinement is not a snapshot of workspace contents. Runtime/auth state
  must remain private and operator-managed. Network, live subscription identity,
  M0.3 controller survival, G12 and broader M1 acceptance remain outside this proof.
